# 架构设计与实现边界

## 1. 目标与交付

项目回答三个问题：冻结骨干的隐状态能否支持内容安全分类；隐状态轨迹相对静态状态和文本特征是否有增益；在固定整回答误报率下，检测器能够在多早的回答位置触发停止。实现以单机可复现流程为主，不引入服务集群、数据库或工作流平台。

交付包括可运行 Python 包、配置、无网络单元测试、数据审计与缓存清单、实际实验指标和图表、英文 IEEEtran 论文、逐节中文对照。所有论文结论均须追溯到保存的实验产物。

## 2. 数据流与组件职责

| 组件 | 输入 | 输出与边界 |
| --- | --- | --- |
| 数据准备 | BeaverTails 及指定外测数据 | 规范化记录、去重审计、分组隔离的划分 |
| 分词及过滤 | 固定 revision 的 tokenizer、chat 模板 | prompt/response token IDs；过长回答过滤，不截断后沿用原标签 |
| 冻结特征提取 | prompt 与完整回答的因果序列 | 指定层、基础 stride 4 的 FP16 检查点状态 |
| 降维拟合 | 仅 train 的抽样检查点 | 每层 64 维 IncrementalPCA 及拟合清单 |
| 流特征派生 | 降维状态、真实 token 位置、选定 stride | 状态、差分、cosine/norm drift；不读未来检查点 |
| 模型训练 | train 前缀及完整回答最终标签 | TF-IDF/LR、静态 LR、prompt-only、单向 GRU |
| 模型选择与校准 | dev、calibration | 超参数选择；基于安全回答整条流最大分数的阈值 |
| 评价与展示 | 固定模型、阈值、test/external | 分类指标、停止位置、误报、资源开销、缓冲演示 |
| 报告 | 保存的预测与指标 | 可追溯图表、表格及中英文论文 |

模块之间通过文件产物和显式函数参数衔接。特征读取接口为：

```python
load_feature_split(
    config, split, stride=None, final_layer_only=False, dynamic=True
) -> (records, sequences, positions)
```

`records[i]`、`sequences[i]`、`positions[i]` 必须对应同一条回答；序列第一维与位置数一致。`positions` 使用从 1 开始的回答 token 计数，不含 prompt、padding 或 EOS。

## 3. 因果契约

设固定 prompt 长度为 \(P\)，回答为 \(y_1,\ldots,y_L\)。检查点 \(t\) 的状态来自消费 \(y_t\) 后的位置 `P + t - 1`。完整因果前向可以一次计算多个检查点，但检查点 \(t\) 不得依赖 \(y_{t+1:L}\)。需要通过完整前向、前缀前向和 KV 增量前向的对齐测试验证这一点。

基础缓存保留 `t % 4 == 0` 和最后一个回答位置；派生 stride 8 或 16 时按真实 token 位置重新选择，始终保留最后位置且不重复。差分与漂移在**选定间隔的降维状态**之间重算；首个检查点的 delta、cosine drift 与 norm difference 均置零。具体拼接和数值公式见[数据协议](data_protocol.md)。

输入禁止使用完整回答长度比例、全回答均值/方差、未来状态及双向时序模型。训练集拟合的固定预处理可用于其他划分；padding 仅通过 mask 或长度参与批处理。

## 4. 缓存、恢复与资源

原始四层 FP16 检查点以分片暂存，并使用 offsets 表达变长回答；训练集每条回答最多抽取 8 个等距检查点拟合每层 PCA。PCA 拟合完成后，将各划分转换为常驻压缩缓存。原始状态清理须在压缩缓存完整性验证后显式进行，避免中断后丢失恢复依据。

层编号对应 Hugging Face 返回的 `hidden_states` 索引；最后一个索引包含骨干末端 RMSNorm，而非额外截取归一化前的 block 输出。两种模型均采用同一接口语义。

缓存身份应覆盖模型/tokenizer revision、chat 模板、层编号、长度限制、检查点规则、数据划分、PCA 工件和配置摘要。分片完成状态须在内容写入并验证之后登记；恢复只复用身份相同且完整的分片。不同配置禁止静默共用缓存。

主实验冻结 0.5B 骨干，使用 `eval()` 和推理模式；先以小批量完成资源探测，再选择固定提取 batch size。原始缓存预计控制在约 15 GB 以内，实际占用以清单记录为准，空间预检应计入权重、原始与压缩缓存共存的峰值。GRU 训练与原始特征提取分阶段运行，不要求同时驻留 GPU。

## 5. 实现与审查检查点

1. 数据审计通过：记录合法、划分无 group 泄漏、过滤计数可追溯。
2. 小样本提取通过：状态/token 对齐、KV 对齐、断点恢复和缓存签名验证通过。
3. train-only 预处理通过：PCA、文本词表及其他拟合统计量不读取 dev/calibration/test/external。
4. 正式运行通过：模型选择先完成，再校准阈值，最后固定配置评价测试集。
5. 生成演示通过：token 先缓冲，风险检查通过后才释放；停止时丢弃当前未释放缓冲。
6. 报告通过：表格数值来自实际产物，两种语言的结论、图表与统计口径一致。
